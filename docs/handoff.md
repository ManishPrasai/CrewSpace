## Decisions and lessons so far (cumulative, most relevant first)
- Resend's `react` email option needs @react-email/render as a peer dependency to actually render JSX (confirmed via the real runtime error) - not part of the approved stack, so email templates use a plain HTML string instead of JSX, avoiding an otherwise-unapproved new dependency for what's a one-paragraph email.
- is_email_workspace_member RPC: auth.users isn't client-queryable and admin.listUsers() has no email filter, so "is this email already a member" needed a small security-definer helper, gated to owner/admin (otherwise it's an email-enumeration probe against an arbitrary workspace).
- PostgREST can only auto-embed a `select()` across tables with a direct foreign key. workspace_members.user_id and profiles.id both reference auth.users(id) but not each other, so embedding profiles inside a workspace_members query fails (PGRST200) - use two separate queries merged by id instead, whenever a query would otherwise join through auth.users as the only common ancestor.
- pgcrypto's digest() lives in the `extensions` schema on this Supabase project, not public - any security-definer function calling it needs `set search_path = public, extensions`, not just public.
- workspace_members' SELECT RLS policy scopes to "any row in a workspace I belong to" (powers the members list), not "only my own row" - queries wanting "my own membership" need an explicit .eq("user_id", userId) filter on top of RLS.
- tests.authenticate_as() leaves the session impersonating that user for the rest of the pgTAP transaction - any verification query against an owner/admin-only table (invitations, workspace update) needs `reset role` first, or it silently returns zero rows (not an error) rather than the real state. This also applies to fixture setup: INSERTs into owner/RPC-only tables (like `workspaces`) must happen before `tests.authenticate_as()` or after a `reset role`, never while impersonating a plain authenticated user, or the insert itself gets rejected by RLS.
- An invite insert for an email with an existing pending (unaccepted, unrevoked) invite fails the partial unique index regardless of why the earlier one is stuck pending (expired, wrong recipient, etc.) - matches docs/database.md's documented note. Test fixtures that create multiple invites for the same email across scenarios need to revoke the prior one first.
- This Supabase project applies ALTER DEFAULT PRIVILEGES on the public schema granting anon its own direct EXECUTE on every new function, separate from PUBLIC. Every RPC needs explicit `revoke ... from public` AND `revoke ... from anon` - verify via has_function_privilege before committing, every time.
- RPCs raise a plain exception with the ErrorCode string itself as the message; the action layer matches on error.message to map back to ActionResult - verified this round-trips correctly, not assumed.
- Hand-rolled test fixture UUIDs need to be RFC4122-compliant (variant nibble 8/9/a/b) or Zod's .uuid() rejects them even though Postgres's own uuid type doesn't care - use gen_random_uuid() for manual psql fixtures.
- Git Bash on Windows auto-converts leading-slash command-line arguments to Windows paths - affects any program's args, not just curl. Use curl's `-F name=<file` syntax (value read from a file), or prefix the command with `MSYS_NO_PATHCONV=1`, whenever a test value starts with "/".
- The raw invitation token only ever exists in the (unsent, since local testing has no real RESEND_API_KEY) email - there's no way to recover it from the DB, which stores only the hash. For e2e-testing the invite accept flow, generate a token with the same `randomBytes(32).toString("hex")` + sha256 scheme as `token.ts` and insert the invitations row directly via psql with that hash - exercises the real preview/accept RPCs and the page/action code without needing a live email provider.
- @supabase/ssr defaults to flowType: "pkce" - confirmation/recovery links carry a `code` param; the PKCE code_verifier cookie set during the initiating action must persist to when /auth/callback runs.
- Stayed on Next.js 15.5.26 per CLAUDE.md's stack lock. `npm audit`'s postcss vulnerability is nested in next's own deps; only fix is Next 16, which the user declined.
- `supabase start`'s parallel image pulls hit persistent TLS handshake timeouts on this network (recurring across sessions). Fix: pull missing images one at a time with plain `docker pull`.
- `supabase_vector_CrewSpace` crash-loops on a Docker-Desktop-on-Windows socket-access quirk every session - only disables Studio's Logs Explorer tab, core services independently verified healthy every time. Left as-is.
- CI workflow runs typecheck/lint/test/build only, not test:db/test:e2e (no Docker/Supabase/browsers in the runner).
- An RLS policy's USING clause filters rows out of an UPDATE/DELETE's view silently - the statement succeeds with 0 rows affected, it does NOT raise 42501 the way an INSERT's WITH CHECK does. Actions that write via plain `.update()/.delete()` (not an RPC) must check `.select("id")`'s returned row count and map 0 rows to FORBIDDEN themselves; pgTAP tests for "X cannot update/delete" must assert on row count, not wrap the statement in throws_ok. This held again for workspaces' delete policy and stripe_events, not just announcements.
- `now()` is frozen for an entire wrapping transaction (pgTAP tests run inside one `begin;...rollback;`), so asserting `updated_at > created_at` right after an update in the same test file will never pass. Test a timestamp trigger by backdating the column first (as an unrestricted role) and asserting the trigger overwrote that specific stale value, not by comparing two same-transaction `now()` calls.
- A client component holding a paginated/cursor-loaded list (loaded beyond the server's first page) can't safely resync from fresh server props after a `revalidatePath` - React won't re-seed a `useState` from changed props, and overwriting it would drop already-loaded pages anyway. Row-level edit/delete actions report their result up to the list owner via callback props instead, so the client array updates directly rather than depending on prop/revalidation timing.
- This `stripe` npm package's API version (`2026-05-27.dahlia`) moved `current_period_end` off the Subscription object onto `subscription.items.data[0].current_period_end`, and moved `invoice.subscription` to `invoice.parent.subscription_details.subscription`. Don't trust remembered Stripe object shapes - grep the installed package's own `.d.ts` files (`node_modules/stripe/cjs/resources/*.d.ts`) before writing webhook handler code against a Stripe resource.
- Completing a real Stripe Checkout/Portal session needs a browser (no Playwright until Day 9), but the webhook handler itself can be fully exercised without one: create real test-mode Stripe objects (customer, subscription) via the API, hand-build the event JSON Stripe would have sent, sign it with `Stripe.webhooks.generateTestHeaderString({payload, secret})` (a real Stripe SDK helper, no network call), and POST it straight to the running `/api/stripe/webhook` route with that signature header. This is a more faithful test than `stripe trigger`, whose fixture events use their own unrelated customer/metadata and can't carry our real `workspace_id`.
- Stripe CLI isn't on npm; installed via `winget install --id Stripe.StripeCli -e` (note lowercase trailing `i` in `StripeCli`, not `StripeCLI` - the exact id is case-sensitive for winget's `-e` exact match). `stripe listen` in this version requires an explicit `--events` list; it no longer forwards everything by default.
- A background dev-server task stopped via `TaskStop` can leave its underlying `node.exe` orphaned and still holding the port (seen repeatedly this session) - check `netstat -ano | grep LISTENING` for the port after stopping and `Stop-Process -Force` the PID if it's still there, before starting a fresh one on the same port.
- Mocking supabase-js's query builder for a Vitest unit test only needs a tiny hand-rolled chainable fake (object literals whose methods return `{ then }` thenables or further chainable objects) scoped to exactly the call shapes the code under test uses - no new mocking library needed, and far less fragile than trying to mock the real `@supabase/supabase-js` client generically.
